Autonomous LiDAR SLAM Rover

MREN 203 Design Project - Winter 2026
ROS 2 HumbleNav2SLAM Toolbox LiDARRaspberry PiArduino PID ControlFoxglove

Engineered as a comprehensive mechatronics design project, this 4-wheel-drive autonomous rover was developed to perform 2D Simultaneous Localization and Mapping (SLAM) and dynamic path planning in unknown environments. Built and demonstrated as a working prototype on a Lynxmotion chassis, the system integrates LiDAR scanning, sensor fusion, and a distributed ROS 2 architecture to achieve real-time autonomous navigation and computer vision-based object detection.

Demo

System Architecture

The platform distributes compute across two layers: an Arduino Uno handles hard real-time sensor reading and motor control, while a Raspberry Pi 4 runs ROS 2 Humble for SLAM, navigation, and image recognition. The two communicate over a serial bridge; a Foxglove Studio HMI connects wirelessly to the Pi's ROS 2 network for remote telemetry, visualization, and manual override.

Chassis & Locomotion

Built on a Lynxmotion A4WD1 kit: four fixed wheels driven by 12V DC planetary gear motors in a skid-steer configuration.

Motor Controller

The custom-designed motor controller translates target linear and angular velocities into left and right PWM signals through a multi-stage process:

  1. Input Conditioning: The system receives target linear and angular velocities. The linear velocity passes through an acceleration limiter, while the angular velocity is corrected by a PID controller using feedback from the IMU Gyro Z sensor.
  2. Differential Kinematics: The updated linear and angular velocities are processed through a kinematics model to calculate the specific target speeds required for the left and right wheels.
  3. Hybrid Wheel Control: Independent controllers process the target speeds for the left and right wheels. Each controller determines the required PWM signal by combining a baseline estimate from a feedforward lookup table with active PID corrections based on encoder feedback.
  4. Output Generation: The calculated PWM for each wheel is checked against a minimum threshold. If it exceeds this minimum, the system outputs a continuous drive signal. Below the DC motors' stall voltage, it switches to a macro-pulse strategy (short pulses at a minimum-viable PWM) to maintain lower speeds accurately.

Perception, SLAM & Navigation

A Slamtec RPLiDAR publishes 2D range data to /scan; a URDF model of the rover defines the physical/kinematic tree so every sensor reading is correctly positioned relative to the chassis. SLAM Toolbox fuses the LiDAR scans with wheel odometry and IMU data via an EKF node to build a 2D occupancy grid map while correcting for odometry drift. Nav2 provides global path planning (A*) and a local planner for dynamic obstacle avoidance, while a Pi Cam feed processed with OpenCV handles localized object detection routines.

Human-Machine Interface

Foxglove Studio connects to the Pi's ROS 2 network over WiFi to render the live SLAM map, the rover's URDF model, camera feed, and hardware telemetry (wheel RPM, PID error, IMU data) without adding compute load to the Pi. It also accepts mission start/target coordinates and manual velocity overrides. A heartbeat timeout on the Arduino side brings the rover to a safe stop automatically if it loses contact with the Pi.
